Philosophy

Why this tool exists

Most EA tooling asks you to hand your organization's architecture data — systems, costs, risk ratings, ownership — to someone else's server. This one doesn't. It's a design decision, not a missing feature.

The EA Landscape Viewer runs entirely in your browser. There's no database, no application server, no account to create, and nothing is ever uploaded anywhere. The "backend" is a folder of plain CSV files that you choose, sitting on your own disk or network share.

For architecture data specifically, that matters: capability maps, application inventories, cost and risk data are often sensitive, sometimes governed by data-residency or confidentiality rules that make "just upload it to a SaaS tool" a non-starter. A tool that structurally cannot exfiltrate your data — because it has no server to send it to — sidesteps that conversation entirely.

It also means the data outlives the tool. Every CSV file this app reads and writes is a completely ordinary CSV — open it in Excel, Numbers, Google Sheets, or a text editor any time, with or without this viewer. If you stopped using this tool tomorrow, you'd lose nothing: your architecture data was never inside a black box to begin with.

Getting Started

From zero to your first map

No server, no install, no build step. The most common way to run this is simply double-clicking the file — which is also the only option that works on many locked-down corporate laptops.

1

Use Chrome or Edge

The app relies on the File System Access API to read and write your CSV folder directly. Firefox and Safari don't implement it yet, so the folder-open step won't work there.

2

Double-click index.html

That's it — Chrome and Edge treat local files as a secure context, so the whole folder read/write pipeline works straight off disk. No terminal, no commands, nothing to install. This is the primary way to run the app.

3

(Optional) Serve it over HTTP instead

If you'd simply rather, or your setup calls for it, a one-line local file host works too — this is not a real backend, just a static file host, and needs no dependencies:

python3 serve.py
# or, if that path doesn't suit your machine:
python3 -m http.server 8080

then visit http://localhost:8080.

4

Click "Open Data Folder"

Pick any folder containing the CSV files described below — start with the bundled data/ sample folder to explore before pointing it at your own architecture data.

The Data Model

Everything is a CSV file

There is no hidden database. Every list, every attribute, every mapping you see in the app is read live from — and written straight back to — one of these files, in the folder you selected.

File Holds
capabilities_l1.csv Top-level capability groups (e.g. "Customer & Marketplace") — name, order, layout, description, owner.
capabilities_l2.csv Sub-capabilities nested under each L1 group, same shape of fields.
applications.csv Your application inventory — ID, name, type, lifecycle, hosting, cost, risk, owner, and any custom columns you add.
app_capability_map.csv The many-to-many links between applications and the L2 capabilities they support.
heading.csv / canvas_heading.csv The title, description, and company name shown in the header and on the printed map.
lov.csv Your team's standard vocabulary — the allowed values for fields like Lifecycle, Risk, and Application Type in the Add/Edit dropdowns.
Why this matters for EAs: a capability map is a living artifact, not a snapshot. Because it's plain CSV, you can commit the folder to git and get a genuine audit trail of how your landscape evolved — who added what application, when a capability was renamed, when an app was marked for decommission — using tools you probably already have, with zero extra tooling.

Printing

Getting the whole map onto one landscape PDF

The app's print styles are built for a large single page — A2 landscape — but the final page size and scale are controlled by your browser's Print dialog, not by the app. This is the single most common point of confusion, so here's the exact sequence.

  1. Click Print in the toolbar (or Cmd/Ctrl + P). All UI chrome — header, sidebars, controls — is automatically hidden; only the map itself is printed.
  2. Set Destination to "Save as PDF".
  3. Set Paper size to A2 if your browser offers it. If not, choose "Manage custom sizes…" (Chrome) and enter a large landscape size — the app is designed around A2 (420 × 594 mm), but any large custom size works the same way.
  4. Set Margins to "None" or "Minimum" to reclaim edge space.
  5. Open "More settings" and set Scale — try "Fit to page" first. If the map still spans more than one page, switch to a manual scale and reduce it a few percent at a time until it fits.
  6. Turn off "Headers and footers" — this removes the browser's own date/URL print header, which otherwise eats into your margin.
  7. Save. You now have the entire capability map as a single-page landscape PDF.
Still spanning multiple pages? Reduce the amount of content the browser has to fit before you print: zoom out in the app (lower the % or hit "Fit to screen"), or switch Density to "Compact" to shrink every block. A smaller canvas at print time means less scaling is needed to land on one page.
Best Practices

Tips for EAs and Solution Architects

A few patterns that make this tool much more useful for governance and team-wide consistency.

Version your CSV folder in git. You get a real, diffable history of your architecture's evolution — who changed what, and when — without any extra tooling.
Standardize lov.csv once, for the whole team. It controls the dropdown options for Application Type, Lifecycle, Risk, Hosting, Region, and Product Category — a shared copy keeps everyone's data consistent, while "Other…" still allows justified exceptions.
Tune color-config.js to your organization's palette (e.g. red/amber/green by Risk, or a gradient by cost) once, and every user who opens the same folder sees the same visual language.
Use the Superseder field on applications.csv to model decommission and replacement chains — the map renders a linked chip straight to the app that replaces it.
Combine multi-select filters to build governance views on demand — e.g. every application that is both Risk: Critical and Lifecycle: Retire, instantly.
FAQ

Troubleshooting

"Open Data Folder" doesn't do anything

Confirm you're using Chrome or Edge — Firefox and Safari don't implement the File System Access API the whole data pipeline depends on, whether the page is opened via double-click or a local server.

My edits don't seem to save

Check for a browser permission prompt asking to confirm read/write access to the folder — it can appear behind the window. Also make sure the CSV file isn't open and locked in another program (e.g. Excel) at the same time.

My printed PDF came out as several pages

See the Printing to PDF section above — this is almost always the browser Print dialog's Paper size/Scale settings, not the app.

Do I need to sign up for anything?

No. There's no account, no cloud service, and no data ever leaves your machine. The only requirement is Chrome or Edge — see Getting Started.

Can I use my own CSV columns?

Yes — any additional column you add to applications.csv is automatically detected and becomes available as a filter and a color-coding attribute, no configuration required.
